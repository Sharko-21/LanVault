# Автоподключение, вся медиатека и прямой LAN — Android 0.2.0

Первое QR-сопряжение остаётся явным и требует сравнения кодов. После него сохранённое доверие используется автоматически. Доступ к CA, токену, оригиналам и каталогу назначения сохраняет ограничения предыдущего MVP.

## Поведение

- Android обходит всю доступную MediaStore-медиатеку страницами по 100 элементов. Это размер буфера, а не лимит числа файлов. Ручной выбор также не ограничен 100 элементами.
- Новый координатор сохраняет receipt каждого файла. Повторный проход пропускает неизменённые подтверждённые версии без чтения содержимого телефона. Не реже чем после 24 часов от последнего подтверждения проверка через прежний idempotency key повторно проверяет серверную копию; пропавшая копия восстанавливается. Смена dataset и устройства доверия не использует чужие подтверждения. Удалённые с телефона файлы не удаляются на ПК.
- Ручной полный запуск использует foreground service с уведомлением, отменой, ограниченным шестью часами wake lock и обработкой системного тайм-аута. WorkManager после короткой проверки ПК может стать долгой foreground-задачей для новых больших видео. Одна фоновая сессия ограничена 55 минутами; завершённые receipt переживают остановку. Общий run lock и mutex операций не допускают параллельных отправок из UI, сервиса и worker.
- Автопроверки запрашиваются раз в 15 минут, при появлении Wi-Fi и изменениях MediaStore. WorkManager хранит расписание после перезапуска. Ограничение низкого заряда, backoff, Doze и квоты Android сохраняются. Непрерывная фоновая работа и мгновенное срабатывание при убитом процессе не обещаются.
- Переподключение сначала проверяет сохранённый IP. Далее используются network-specific NSD на Android 13+ и ограниченный TCP-поиск на прежнем порту в собственном /24 (или меньшей реальной подсети). В фоне такой запасной поиск выполняется не чаще раза в 15 минут; ручной полный запуск может запросить его сразу. Максимум 253 адреса, 16 коротких одновременных соединений, до 8 кандидатов. Широкие подсети /8 не сканируются целиком. IP из объявления не становится доверенным без проверки TLS, CA pin, hostname и serverId; токен не отправляется до TLS-проверки.
- Desktop объявляет `_lanvault._tcp.local.` только через выбранный физический частный IPv4-интерфейс. TXT содержит serverId и версию протокола, без QR-секрета и токена. Приём запоминает адаптер по GUID, восстанавливается после запуска и смены его IP. Явная команда «Остановить» отключает восстановление. Приложение Windows должно оставаться запущенным; вход в Windows автоматически его пока не запускает.

## VPN и границы маршрута

На Android больше нет blanket-запрета активного VPN. Фабрика сокетов принадлежит конкретному физическому Wi-Fi Network; проверяются частный IPv4, одна подсеть и отсутствие VPN/cellular transport у выбранного Network. Запросы, резервный поиск и NSD не используют процессный default network, публичный DNS, HTTP proxy или cellular fallback.

На Windows `IP_UNICAST_IF` устанавливается на TCP-сокет до bind/listen и на принятое соединение; значение interface index передаётся Winsock в сетевом порядке байтов. Listener по-прежнему привязан к одному частному физическому адресу, разрешены только соседи его подсети. VPN-маршрут по умолчанию не выбирается вместо него.

Это выбор маршрута, а не обход политик безопасности. VPN kill switch, Android lockdown или драйвер, запрещающий прямой LAN, может блокировать эти сокеты. Пользователь должен разрешить локальную сеть/обход для LanVault в VPN. Программа не отправляет файлы через VPN в качестве запасного пути. См. [Android VPN allowBypass](<https://developer.android.com/reference/android/net/VpnService.Builder#allowBypass()>).

## Проверки и практические ограничения

- Android debug APK и instrumentation APK собираются. JVM-проверки включают реальный Kotlin → Windows TLS: 137 файлов на нескольких страницах, остановку после 110 receipt, продолжение оставшихся 27, повтор без чтения содержимого, ручной выбор 137 файлов и изменение одной версии. Дополнительно проверяются границы LAN-поиска и запрет использовать receipt старого deviceId после повторного сопряжения.
- Обычные Rust-тесты, Clippy и HTTPS-набор проверяют прежние ограничения хранения, TLS и авторизации. Отдельный opt-in тест физического LAN проверяет закрепление сокета за Ethernet, сохранение/восстановление адаптера и отмену восстановления после «Остановить».
- В этой сети объявления mDNS зарегистрированы на Ethernet, но локальный multicast-browse не получил ответа: это наблюдалось и в opt-in тестовом EXE, и через диагностику самого Desktop. Поэтому добавлен запасной прямой TCP-поиск. Этот multicast-тест не выдан за пройденный. На настоящем телефоне получение NSD, смена DHCP-адреса и работа foreground/WorkManager с VPN ещё не проверены: телефон не подключён через ADB.
- Передача остаётся whole-file. После обрыва большого видео подтверждённые соседние файлы пропускаются, а незавершённое видео отправляется с начала. Файл больше 4 ГиБ, Android power/Doze/FGS-квоты и многосуточная библиотека требуют испытания на устройстве. [Ограничения Android для долгих workers](https://developer.android.com/develop/background-work/background-tasks/persistent/how-to/long-running).
- При ограниченном разрешении Android синхронизируются только разрешённые файлы, а не содержимое приватных каталогов других приложений или cloud-only медиа. Оригиналы не перекодируются и не удаляются.

Результаты сборок, тестов и lint находятся в игнорируемых `artifacts/android-auto-final-check.log`, `artifacts/desktop-auto-runtime.log` и XML-отчётах Gradle. Рабочий APK: `artifacts/android/LanVault-0.2.0-auto-debug.apk`. Предыдущие отчёты этапов описывают состояние до этой работы.
