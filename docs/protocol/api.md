# Контракт v1 — публичная beta

Статус: HTTPS-маршруты реализованы и проверяются настоящим клиентом. Машиночитаемый контракт: [OpenAPI 3.1](openapi.json). Валидация дескриптора: `protocol/schemas/upload-descriptor.schema.json`; размер и счётчики байтов передаются десятичными строками.

| Метод  | Путь                                         | Поведение                                                                           |
| ------ | -------------------------------------------- | ----------------------------------------------------------------------------------- |
| POST   | `/v1/pairing/requests`                       | QR-секрет + имя + отдельный client claimSecret; локальное подтверждение обязательно |
| GET    | `/v1/pairing/requests/{id}`                  | `X-Pairing-Claim`; повторяемая выдача токена после подтверждения                    |
| POST   | `/v1/pairing/requests/{id}/confirm-received` | Удалить зашифрованный результат выдачи                                              |
| GET    | `/v1/server`                                 | Bearer token; возможности и пауза                                                   |
| GET    | `/v1/datasets/current`                       | Dataset UUID и свободное место без абсолютного пути                                 |
| POST   | `/v1/uploads`                                | Валидация, резерв места, идемпотентность и проверенная дедупликация                 |
| GET    | `/v1/uploads/{id}`                           | Только владелец: стадия, диагностические байты либо подтверждение                   |
| DELETE | `/v1/uploads/{id}`                           | Отмена своего незавершённого задания и удаление его staging-файла                   |
| PUT    | `/v1/uploads/{id}/content`                   | Весь оригинал, точный Content-Length, без Content-Encoding                          |
| POST   | `/v1/uploads/{id}/complete`                  | Полный SHA-256 → журнал → публикация без перезаписи → DB commit → receipt           |

Всё передаётся через TLS 1.2/1.3. QR содержит публичный CA, SPKI SHA-256, стабильное TLS-имя `<serverId>.lanvault.invalid`, IPv4/порт и одноразовый секрет. Клиент соединяется с этим IPv4 с указанными SNI/hostname, проверяет цепочку к QR CA и отпечаток его ключа. Имя `.invalid` не требует внешнего DNS. Доверие к сертификату нельзя отключать. Пример реализации соединения — `Connection` в `tooling/test-server.py`.

Секрет QR действует 120 секунд и потребляется одним запросом. Новый QR, закрытие окна QR или остановка сервера отменяют прежние открытые/ожидающие запросы. После локального сравнения шестизначного hex-кода выдаётся отдельный 256-битный токен устройства. Его SHA-256 хранится в таблице устройств; временный повторяемый результат выдачи зашифрован DPAPI на срок до 5 минут. Клиент сначала устойчиво сохраняет токен, затем вызывает confirm-received. Административных HTTP-маршрутов нет: выбор папки, подтверждение и отзыв доступны через Tauri IPC или локальный stdin CLI.

## Передача и подтверждение

`GET /v1/server` сообщает `capabilities.maxConcurrentUploads`: текущий приёмник допускает четыре одновременных тела файлов. Android выбирает минимум своего лимита и значения сервера. Для прежнего сервера с лимитом два сохраняются две задачи; при отсутствии capability клиент использует два. Версия протокола, сертификаты, токены и dataset при обновлении не меняются.

1. Получить текущий dataset UUID.
2. Создать дескриптор с новыми `mediaId`, `revisionId`, `uploadRequestId` и полным SHA-256 оригинала. Последующие повторы этой операции используют тот же дескриптор.
3. Если POST уже вернул `committed`, сохранить receipt. Иначе отправить весь файл через PUT с точным Content-Length.
4. После `verified` вызвать complete; устойчиво сохранить receipt. Разрыв до ответа complete разрешается повтором complete/GET/POST с исходным идентификатором.

Одинаковый request UUID с другими метаданными возвращает 409. Дедупликация ограничена устройством и dataset; существующий файл заново хешируется, а новый receipt относится к новым media/revision UUID. Повторное подтверждение сохранённого файла тоже проверяет наличие и хеш. Удалённая или повреждённая внешним действием копия не получает повторного успешного подтверждения.

`receivedBytes` — диагностический счётчик. `resumable:false`: прерванная передача повторяется с нуля. Устойчивые части/offset и PATCH пока отсутствуют, как и `/files/probe`, сетевые history/receipts и ротация credentials. История и отзыв доступа доступны локально через Desktop. Сохранённые файлы не удаляются по сети.

`DELETE /v1/uploads/{id}` возвращает состояние отменённого задания. Для чужого UUID возвращается 404; для активного тела, `committing` или `committed` — 409. Отмена не затрагивает опубликованный архив. Тот же исходный дескриптор можно повторно отправить через POST: отменённое задание переоткрывается с прежним ID после проверки квот. Дескриптор с изменёнными полями по-прежнему отклоняется.

Незавершённые задания имеют lease 24 часа. Создание, повтор и запись продлевают lease; очистка пропускает активную запись и commit. Она освобождает очередь и staging текущего архива, не удаляя сохранённые файлы и не обращаясь к старому неактивному корню. Прежние задания без lease учитываются по времени создания. Это позволяет старым клиентам продолжать работу без нового сопряжения.

## Ограничения и ошибки

Не более четырёх одновременных тел файлов, 32 TLS-соединений, 16 незавершённых заданий на устройство, 320 суммарно и 20 активных устройств; максимум 1 ТиБ на файл. Метаданные JSON ограничены 16 КиБ. Для GUI резервируется 512 МиБ свободного места сверх файлов и ожидающих резервов. Handshake — 5 секунд, заголовки — 10, простой тела — 30. Запросы сопряжения ограничены 10 в минуту. Все запросы с Origin отвергаются; CORS не разрешён.

Основные коды: 400 некорректный запрос; 401 нет доверия; 404 нет объекта/не тот владелец; 409 конфликт состояния; 410 истёк срок; 413 слишком большой запрос; 422 SHA-256 не совпал; 423 пауза; 429 лимит; 503 недоступно хранилище/сеть; 507 нет места. Ошибки ядра — JSON `{code,message}` без секретов и абсолютных путей; ошибки парсера HTTP/JSON могут быть обычным текстом. 500 всегда означает отсутствие нового подтверждения успешного сохранения. Повторять слепо после 409 нельзя: сначала прочитать стадию и dataset.

Серверный каталог: `metadata`, `roots`, `devices`, `pairing`, `uploads`, `receipts`, `upload_leases`. Таблица lease добавлена совместимо с schema 1. SQLite WAL, synchronous FULL, foreign keys, одно соединение. Новая неизвестная версия схемы отклоняется до миграции. При старте завершённые файлы проверяются по наличию и размеру; `committing` восстанавливается с полным хешем до или после rename. Полный SHA-256 обязателен также при публикации и перед повторной выдачей квитанции. Проверка staged-файла выполняется вне общей блокировки; публикация и SQLite commit остаются сериализованы с повторной проверкой устройства и dataset. Информационная метка `last_seen` пишется не чаще раза в минуту, но токен и отзыв доступа проверяются по базе на каждом запросе.
