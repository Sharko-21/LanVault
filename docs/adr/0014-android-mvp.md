# ADR-0014 — Android MVP

Статус: Accepted, реализация этапа 4; сохраняет утверждённый стек и wire contract v1.

Добавлен модуль `core:transport` (Kotlin/JVM). Он содержит проверку доверия, HTTPS, ручную передачу и интерфейсы источника, журнала и защищённого состояния. Android `core:network` предоставляет Wi-Fi SocketFactory и живую политику; `core:media`, `core:database` и `core:security` реализуют MediaStore, Room и Android Keystore. Такое разделение позволяет проверить настоящий клиент против Windows EXE без подмены TLS и без Android runtime. Тестовая SocketFactory перенаправляет один фиктивный private IP в loopback; в приложении такой фабрики и разрешения loopback нет.

Сопряжение использует QR этапа 3: лимит входа 32 КиБ, версия 1, UUID/hostname, RFC1918 IPv4, TTL, self-signed CA с CA/keyCertSign, срок сертификата и SHA-256 SPKI. TLS доверяет только этому CA и сохраняет стандартную проверку hostname плюс CertificatePinner. HTTP redirects, proxy и автоматический сетевой retry отключены; внешнего DNS нет. Одобрение выдаёт Desktop после сравнения кода. Claim и ожидающий request сохраняются до запроса, credentials — до confirm-received. Незавершённая выдача восстанавливается с тем же claim/request, включая уже одобренную выдачу после истечения QR в пределах серверного окна.

Долгоживущий токен и pending pairing хранятся в AtomicFile под AES-256-GCM, ключ — Android Keystore, AAD привязан к версии и namespace. Каталог noBackupFilesDir, резервирование приложения отключено. Повреждение шифротекста не сбрасывает доверие молча; пользователь может явно забыть подключение. Это не обещание hardware-backed Keystore на каждом телефоне. [Android Keystore](https://developer.android.com/privacy-and-security/keystore).

Соединение использует конкретный существующий Wi-Fi Network и его SocketFactory. Разрешён private IPv4 того же префикса; cellular/VPN транспорты и активный VPN отклоняются. Не требуется INTERNET/VALIDATED capability: LAN может работать без WAN. Политика проверяется на запросах и блоках отправки, callbacks закрывают соединение при потере сети/изменении свойств. Процесс целиком к сети не привязывается. Android 17 требует отдельного runtime ACCESS_LOCAL_NETWORK; запрос показывается перед подключением/передачей. [Разрешение LAN](https://developer.android.com/privacy-and-security/local-network-permission).

MediaStore читается страницами по 100 с keyset pagination, отдельно по доступным томам/типам; pending и trash исключены. Область разрешений явно видна пользователю, ограниченный доступ не объявляется полной библиотекой. Используются content URI, без DATA/абсолютных путей и MANAGE_EXTERNAL_STORAGE. Для отправки требуется ACCESS_MEDIA_LOCATION; применяются setRequireOriginal и на API 31+ getOriginalMediaFormatFileDescriptor. Если исходные байты недоступны, нет скрытой подмены редакторской копией. [MediaStore и исходные метаданные](https://developer.android.com/training/data-storage/shared/media), [API исходного формата](https://developer.android.com/reference/android/provider/MediaStore).

Ручная серия — до 100 файлов, последовательно. Сначала потоковый SHA-256, затем проверка версии источника, устойчивый descriptor/request UUID в Room, создание upload, потоковый PUT, complete и проверка всех полей receipt. Буфер 128 КиБ, размер Long/десятичная строка. Повтор сохраняет request UUID, пропускает уже verified/committing тело и заново подтверждает готовую копию. Исчезнувшая копия по явному SAVED_FILE_UNAVAILABLE заменяется новым upload request; ложный cached success не принимается. Room WAL/FULL; незавершённые стадии после старта становятся INTERRUPTED. JSON хранит дескриптор, SQL-стадия служит текущим состоянием.

Уход с экрана или «Остановить» отменяет coroutine и HTTP call. Исключения отмены/источника внутри OkHttp RequestBody переводятся в IOException, чтобы не завершать Android-процесс необработанным runtime exception. Сохранённый файл на телефоне не удаляется. Foreground service, UIDT, WorkManager-очередь передачи и устойчивые части остаются следующими этапами; MVP честно повторяет тело с нуля.

Камера QR использует ZXing Embedded 4.3.0 локально, без Google Play Services и сетевой загрузки модели. [Библиотека и ScanContract](https://github.com/journeyapps/zxing-android-embedded). Transport использует проверенный OkHttp 4.12.0; варианты обновления pinned-зависимостей отмечает lint, они не менялись вслепую в этом этапе.

Для Windows-сборки в текущей кириллической папке введена проверяемая ASCII TEMP-копия входных файлов, а не переименование репозитория и не подмена SDK. Реально установлен официальный `platforms;android-37.0`, который AGP 9.1.1 принимает для compileSdk 37. Подготовленные инструменты локальные и не входят в Git. Переносимый JDK 17.0.21+9 и command-line tools проверены по опубликованным SHA-256. APK и инструментальные тесты собираются; выполнение instrumentation отдельно отмечается по факту наличия устройства.
