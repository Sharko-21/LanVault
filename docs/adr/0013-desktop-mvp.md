# ADR-0013 — Desktop MVP и безопасная запись

Статус: Accepted, реализация этапа 3; дополняет утверждённую архитектуру и обновляет Rust из ADR-0012.

Desktop использует единое Rust-ядро `lanvault-server`: Tauri IPC и диагностический `lanvaultd` обращаются к тому же Engine. React не получает API произвольной записи или запуска команд. Удалённого административного HTTP нет.

Передача MVP — поток целого файла с точным размером, ограниченным буфером и полным SHA-256. Сервер явно сообщает `resumable:false`; части и устойчивый offset остаются этапом 6. Это позволяет проверить путь от TLS до durable receipt, не объявляя частичное восстановление готовым.

Хранилище поддерживает обычный локальный NTFS-каталог вне известных корней OneDrive. Каждый компонент открывается относительно живого дескриптора родителя через NtCreateFile с OBJ_DONT_REPARSE/FILE_OPEN_REPARSE_POINT. Дескрипторы каталогов с FILE_LIST_DIRECTORY не разделяют DELETE, сохраняя идентичность предков. Файлы должны быть обычными, с одним hard link; ADS и опасные компоненты отклоняются. Имена клиента используются только как метаданные/санитизированный суффикс; сервер генерирует UUID. Публикация — NtSetInformationFile(FileRenameInformation) относительно дескриптора назначения, ReplaceIfExists=false. Ни создание, ни публикация не разрешают запись по собранному абсолютному пути. [NtCreateFile](https://learn.microsoft.com/en-us/windows/win32/api/winternl/nf-winternl-ntcreatefile), [NtSetInformationFile](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-ntsetinformationfile).

Порядок фиксации: sync временного файла → полная проверка → устойчивое намерение `committing` → rename без перезаписи → sync живого дескриптора → транзакция receipt и `committed` с synchronous FULL. Дескриптор файла удерживается до DB commit. Повтор и восстановление сравнивают реальные байты; наличие строки в БД не заменяет проверку копии. Гарантия зависит от честного выполнения flush накопителем; отключение питания физического устройства в этой среде не испытывалось.

CA ECDSA P-256 и server UUID сохраняются под DPAPI текущего пользователя. Сертификат сервера выпускается при каждом старте со стабильным hostname и тем же CA. Состояние имеет защищённый DACL (текущий пользователь и SYSTEM); папке архива ACL не меняется. Администратор или вредоносный процесс того же Windows-пользователя находятся за границей этой модели защиты. DPAPI не делает состояние переносимым на другой аккаунт/компьютер.

Сеть выбирается явно: физический адаптер, Private, RFC1918 IPv4 и тот же префикс для peer. Нет bind на wildcard, Public, VPN или виртуальный адаптер. Изменение сети проверяется раз в 5 секунд и останавливает сервер; запрос сведений Windows ограничен 5 секундами. Для MVP используется фиксированный read-only PowerShell NetTCPIP/NetAdapter/NetConnectionProfile без пользовательской интерполяции и с CREATE_NO_WINDOW. Ошибка закрывает приём. Нативные события NLM, discovery, IPv6 и уточнение поведения брандмауэра относятся к следующим этапам. Профиль сети и правила брандмауэра автоматически не изменяются.

Rust обновлён с 1.90.0 до **1.94.0**: выбранный SQLx 0.9 требует MSRV 1.94. Lock-файл, toolchain, doctor и CI синхронизированы. Поддерживаемая сборка релиза остаётся Windows MSVC. На текущей машине без MSVC/SDK дополнительно выполнены сборка и запуск Windows GNU с официальным Rust 1.94.0 и LLVM-MinGW 20261020 MSVCRT; файлы инструментов локальные, суммы загрузок сверялись. Это отдельная проверка Windows-поведения, а не сертификация MSVC/установщика. Desktop library собирается как rlib: C ABI/staticlib здесь не используются.
