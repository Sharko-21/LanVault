# Запуск Android MVP

Нужны Android 10+ и Desktop. Готовый debug APK: `artifacts/android/LanVault-0.2.2-speed-debug.apk` (также `app-debug.apk`). Версия приложения: `0.2.2-speed` (versionCode 6). Установите APK поверх предыдущего, сохранив данные, чтобы сохранить доверие к ПК. Полная и ручная отправка используют до четырёх очередей, согласованных с Desktop; с прежним приёмником сохраняется лимит два. Подпись совпадает с 0.2.1, схема Room и Keystore не менялись. [Результаты оптимизации](../stages/stage-07-speed.md), [исправление ASTER](../stages/stage-06-parallel.md). Подпись APK пока debug.

## На телефоне и компьютере

1. На ПК запустите Desktop по [инструкции](development.md), выберите обычную локальную NTFS-папку вне OneDrive, частный физический адаптер и включите приём. Порт 43827/TCP, выбранный IPv4. Профиль Windows и брандмауэр приложение автоматически не меняет.
2. Подключите телефон к Wi-Fi той же подсети. VPN можно оставить включённым: запросы привязаны к физическому Wi-Fi, ответы ПК — к выбранному физическому адаптеру. Если VPN или режим «Блокировать соединения без VPN» запрещает прямую локальную сеть, разрешите LAN/обход для LanVault в настройках VPN. Само приложение не может отменить системный запрет. Интернет-валидация Wi-Fi не требуется; мобильная сеть не служит запасным маршрутом.
3. Установите APK через ADB или обычный разрешённый на устройстве способ установки debug APK. Для ADB с уже разрешённой отладкой:

```powershell
adb devices
adb -s SERIAL install -r artifacts/android/app-debug.apk
adb -s SERIAL shell am start -n app.lanvault.android/.MainActivity
```

4. На Desktop нажмите «Подключить телефон». В Android — «Сканировать QR-код», затем «Подключиться». На Android 17 разрешите локальную сеть. Сравните код на обоих устройствах и подтвердите на Desktop. QR действует две минуты.
5. Нажмите «Доступ к медиа», разрешите все фотографии и видео и исходные метаданные. В карточке «Вся медиатека» включена автосинхронизация. «Синхронизировать всё» запускает полную проверку сразу; выбирать каждую фотографию не требуется. Первая страница из 100 строк ограничивает только отображаемый список. Автоматическая загрузка обходит все страницы независимо от открытых строк; у ручного выбора тоже нет лимита 100.
6. Разрешите уведомления. Большая загрузка работает с foreground-уведомлением и удержанием CPU при выключенном экране. Пауза в интерфейсе или уведомлении сохраняется. После первого сопряжения QR повторно не нужен: проверяются сохранённый адрес, mDNS на Wi-Fi и при необходимости один локальный /24 диапазон (либо меньшая реальная подсеть). Новый адрес сохраняется только после проверки прежнего CA, hostname, serverId и токена.
7. WorkManager проверяет новые файлы периодически (интервал запроса 15 минут) и по событиям Wi-Fi/MediaStore, пока процесс наблюдения жив. ОС может отложить задачу; учитываются заряд батареи, Doze, квоты фоновых работ и foreground service. Принудительная остановка приложения блокирует фон до следующего запуска. Подтверждённые файлы не передаются повторно. Для прерванного незавершённого файла пока повторяется всё тело; chunk-resume остаётся следующей работой.

Desktop должен быть запущен (можно в трее). После включения приёма сохраняется выбранный адаптер, и приём восстанавливается при следующем запуске и возвращении этой частной физической сети. «Остановить» отменяет восстановление. Автозапуск самого Windows-приложения вместе с ОС в этой версии не настраивается.

Оригиналы на телефоне остаются. Смена папки Desktop меняет dataset; старые подтверждения не выдаются за копии в новом архиве. При отзыве устройства на Desktop нужно забыть подключение в Android и выполнить новое сопряжение. «Забыть ПК» удаляет доверие только с телефона; старую запись можно отозвать на компьютере.

В проверке этапа 3 не был найден разрешённый Private-адаптер. В этапе 4 связь с физическим телефоном не испытывалась. Использованные loopback interop-тесты сохраняют CA, hostname, авторизацию и оригинальные байты; они не заменяют испытание двух устройств в LAN.

## Если подключение не удаётся

В версии `0.1.1-stage4` сообщение различает этапы соединения. Исключения не выводят исходные тексты, URL, QR-секреты или токены.

| Код                                                   | Что проверить                                                                                                                                          |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `TCP_CONNECTION_TIMEOUT`                              | Телефон не установил TCP-соединение с ПК за 10 секунд. Приём Desktop, VPN на ПК, разрешение локальной сети, гостевая сеть или изоляция клиентов Wi-Fi. |
| `TCP_CONNECTION_FAILED`, `TCP_NETWORK_FAILED`         | Приём Desktop и доступность адреса из QR, сетевые ограничения.                                                                                         |
| `TLS_HANDSHAKE_TIMEOUT`, `TLS_CONNECTION_CLOSED`      | TCP доступен, но TLS не завершён. Состояние Desktop и сетевые фильтры.                                                                                 |
| `DESKTOP_RESPONSE_TIMEOUT`, `DESKTOP_CONNECTION_LOST` | Защищённое соединение было установлено, но ответ не получен. Состояние приёма и обрыв Wi-Fi.                                                           |

Ошибка проверки CA или имени сервера по-прежнему запрещает подключение. Проверки доверия не отключаются ради диагностики. При истечении двух минут на Desktop нажмите «Обновить QR-код» и отсканируйте новый код.

Версия `0.1.2-stage4` исправляет чтение уже исходных файлов (в том числе PNG-скриншотов) на Android 12+: оригинальный формат запрашивается сразу через `EXTRA_ACCEPT_ORIGINAL_MEDIA_FORMAT`, вместе с `setRequireOriginal` для исходных метаданных. Повторное преобразование дескриптора через `getOriginalMediaFormatFileDescriptor` больше не используется: MediaProvider может отклонять его для уже исходного формата. См. [официальный контракт флага](https://developer.android.com/reference/android/provider/MediaStore#EXTRA_ACCEPT_ORIGINAL_MEDIA_FORMAT). Для действительно недоступного оригинала показывается `MEDIA_FILE_UNAVAILABLE`. Обновление APK поверх установленного приложения сохраняет доверенный компьютер; повторное сопряжение не требуется.

## Повторить сборку и проверки

На этой машине подготовлены переносимые инструменты в `.tools`, без системной установки:

```powershell
.\tooling\check-android.ps1 -Portable -DesktopServerExe .\target\gnu\debug\lanvaultd.exe
```

Скрипт создаёт точную копию Android/protocol в `%TEMP%/LanVault-android-build`, проверяет SHA-256 входов, использует JDK/SDK с латинским путём, собирает основной и тестовый APK, выполняет lint и JVM-тесты. Так обходится сбой Gradle WorkerMain на кириллическом пути. Репозиторий остаётся в исходной папке. Готовые APK и lint XML копируются в `artifacts/android`, Room schema — в исходники. Журнал: `artifacts/android-final-check.log`.

Без Desktop EXE девять Windows interop-тестов явно пропускаются. Для обычного окружения с JDK 17, Android SDK 37.0/Build Tools 36.0.0 и латинским путём:

```powershell
sdkmanager "platforms;android-37.0" "build-tools;36.0.0" "platform-tools"
.\tooling\check-android.ps1
```

Те же действия доступны через `tooling/check.ps1 -Target Android -PortableAndroid -AndroidServerExe PATH`. На другой машине `.tools` не поставляется с Git: настройте официальный JDK/SDK либо подготовьте локальные инструменты. [Android command-line tools](https://developer.android.com/studio), [полная инструкция](development.md).

## Проверки на устройстве

Подготовлены шесть instrumentation-тестов: checkpoint Room, шифрование/перезапуск Keystore, изменение ciphertext, восстановление transfer journal, MediaStore original/pending и полный Android → Desktop. Они создают собственные синтетические файлы/БД/namespace ключа и убирают их. Обычная проверка требует доступного устройства:

```powershell
.\android\gradlew.bat -p android :app:connectedDebugAndroidTest
```

Полный E2E требует отдельного тестового Desktop и стандартного Wi-Fi/host mapping эмулятора. Воспроизводимый helper (не проверен запуском здесь из-за недоступного эмулятора):

```powershell
python tooling/test-android-device.py --adb PATH_TO_ADB --serial emulator-5580 --apk artifacts/android/app-debug.apk --test-apk artifacts/android/app-debug-androidTest.apk --desktop-exe target/gnu/debug/lanvaultd.exe
```

Helper запускает отдельный Desktop на loopback, сравнивает коды, подтверждает только своё синтетическое устройство и проверяет SHA-256 файла на диске. Для физического телефона не задавайте `--desktop-exe`; ручной LAN-сценарий выполняйте через GUI и настоящий QR. Тесты автоматически предоставляют разрешения тестовому приложению, не проверяют реальные системные диалоги камеры/медиа.

Здесь instrumentation **не выполнен**: телефона нет, гипервизор отсутствует, программный эмулятор завершился с `0xC0000005`. Сборка тестового APK не считается прохождением этих тестов. [Точные результаты](../stages/stage-04.md).
