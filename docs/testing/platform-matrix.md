# Платформенная проверка этапа 2

Исходники диагностик подготовлены. Таблица ниже — план испытаний на оборудовании, а не результаты.

| Проверка       | Среда                           | Критерий                                                                 |
| -------------- | ------------------------------- | ------------------------------------------------------------------------ |
| MediaStore     | Android 10, 13, 14, 16, 17      | Реальный охват разрешений; выбранные медиа не выдаются за всю библиотеку |
| Оригинал       | JPEG/HEIC и EXIF GPS            | Получены исходные байты или явный отказ; нет скрытой подмены             |
| NSD            | Wi-Fi и Ethernet одного роутера | Обнаружение объявления после появления настоящего сервера                |
| LAN без WAN    | Роутер без интернета            | Проба выполняется; интернет-валидация не блокирует её                    |
| Permission     | Android 17 / target 37          | Отказ и отзыв ACCESS_LOCAL_NETWORK дают понятное состояние               |
| SHA-256        | JVM, затем Room instrumentation | Тот же хеш после checkpoint, закрытия БД и восстановления                |
| Windows shell  | Windows 10 22H2 / Windows 11    | Окно, диалог, свободное место, скрытие и выход через трей                |
| Secure storage | NTFS                            | Защита записи проверяется только после реализации Storage Adapter        |
| TLS            | Android ↔ Windows              | Доверенная цепочка проходит; подмена и неверное имя отвергаются          |

TLS и защищённая запись не заменяются заглушками в этапе 2: их эксперимент требует реального кода приёмника и полного toolchain, поэтому остаётся входной проверкой этапа 3. До неё LAN listener не создаётся.

GitHub CI собирает Android APK и APK instrumentation-тестов, запускает JVM-тесты и lint. Выполнение instrumentation требует отдельного устройства/эмулятора и не входит в текущий автоматический job. Desktop job проверяет Rust и собирает EXE. Наличие workflow не является прохождением CI.

## Результаты этапа 3

Нативный Windows GNU Desktop и сервер собраны, 14 Rust-тестов и 23 настоящих HTTPS-сценария проходят. Подробные результаты, границы GUI-проверки и команды: [отчёт этапа 3](../stages/stage-03.md). Таблица этапа 2 выше остаётся планом испытаний на реальном оборудовании. Android, MSVC release, физическая LAN, QR-камера, файлы >4 ГиБ, извлечение диска, питание и нагрузка не объявляются проверенными.

## Результаты этапа 4

Android debug APK и instrumentation APK собраны. 30 JVM-тестов проходят, включая 9 против реального Windows Desktop; lint: 0 ошибок и 20 предупреждений об обновлениях. Device instrumentation не выполнен: телефона нет, программный Android 17 эмулятор завершился с 0xC0000005. Сборка тестов не считается их прохождением. Подробная матрица и команды: [этап 4](../stages/stage-04.md), [Android MVP](../installation/android-mvp.md).
